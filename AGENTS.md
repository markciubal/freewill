# Freewill project conventions

Read BUILD_PROMPT.md first. It is the constitution and the task list.

- **No authority.** Never add an admin, moderator, or issuer role. Decisions come from a computed rule (`src/lib/standing.ts`), a steward accountable via standing, or a circle.
- **Ledger invariants.** Every balance change goes through `transfer()` in `src/lib/ledger.ts` inside a transaction. Sum of all balances on each ledger must stay zero. Hours are stored in minutes.
- **Auth.** Username + password only (`src/lib/auth.ts`). No email, no resets, no OAuth. Use `requireUser()` in server components and actions; never trust client input for identity.
- **Server actions.** One `actions.ts` per area under `src/app/(app)/<area>/`. Validate with zod. Errors redirect back with `?error=` via `fail()` from `src/lib/form.ts`; success with `ok()`. Guard ObjectIds with `isObjectId()` before `findUnique`.
- **Next 16.** `params` and `searchParams` are Promises. `cookies()` is async. Use `LayoutProps`/explicit prop types.
- **Prisma 6 + MongoDB.** Enums and `String[]` are fine. `$transaction` requires a replica set. IDs are ObjectId strings.
- **UI.** Use the primitives in `src/components/ui.tsx`. Copy addresses a tired, frightened person: short, plain, civic, tells them what to do next. Never vow-like or in-group ("affirm", "give my word", mottoes). Code names differ from UI labels: covenant = "ground rules", Circle = "dispute", keeper = "mediator" — keep code identifiers, translate in UI strings. Survival categories (`SURVIVAL` in covenant.ts) sort first.
- **After any feature work,** update `src/lib/covenant.programs.ts` (live/planned) and BUILD_PROMPT.md section 5.
- **Verification and locality.** `locality` is required and editable on the profile (the map pin is not). Store it through `normalizeLocality` (trim + collapse whitespace only — never lowercase or strip characters). Match case-insensitively: `scopeWhere` uses `mode: "insensitive"`, and in-memory grouping uses `localityKey` (both in `src/lib/form.ts`/`geo.ts`). Use `getStanding` from `src/lib/standing.all.ts`; `standing.verified` gates credit, vouching, keeping, proposing, voting.
- **Demurrage.** `maybeRunDemurrage()` is idempotent per 30 days; the zero-sum check must include `latestRun().remainder`.
- **Keepers are drawn, never chosen.** Use `fillKeepers()` from `src/lib/keepers.ts`; never add a self-selection path.
- **Geography.** `lat`/`lng` on User are chosen at join and editable on the profile, always through `roundPin`. Everything else from sign-up except the username is editable there too; the password can be changed with the current one but never reset (`PasswordKeeping` carries the keep-it-safe advice on join and profile). Never render a person as a map point; show `fmtDistance(haversineKm(me, them))`. Records people publish copy `me.lat/me.lng` at creation. Use `applyNear` for the "near" scope; never add a geocoder or automatic geolocation.
- **Theming.** UI colors/type/shape come only from the custom properties in `src/lib/theme.ts` (`--background`, `--accent`, `--warn`, `--radius`, `--font-size`, `--content-width`...). Use token utilities (`bg-card`, `text-warn`, `rounded-md`, `max-w-(--content-width)`), never hard-coded palette classes like `amber-600`. Per-person themes are validated by `sanitizeTheme` and injected from the root layout; never inject raw user CSS.
- **Grace amounts.** Grace is stored in **cents** (hundredths). Human input is multiplied by 100 in actions; display divides by 100 via `fmtGrace`/`<Grace n={cents} />` (n is cents). Standing `graceLimit` is in cents. Hours stay in minutes. Cash `denomination` is whole Grace (1-100); multiply by 100 for money math and display. Never pass whole Grace to `<Grace>`.
- **Databases.** `src/lib/db.ts` picks `DATABASE_URL_PROD` when `NODE_ENV=production`, else `DATABASE_URL_DEV`, falling back to `DATABASE_URL`. Scripts that make their own PrismaClient must use `databaseUrl()` from db.ts. Never seed or reset prod.
- **Trade pulse.** Reflections (`src/lib/pulse.ts`) measure welfare, never people: show aggregates only, never per-person answers, and never let them feed standing or any ranking.
- **ID.me affiliation verification (exception to "no OAuth").** Attestation only, never login, behind IDME_ENABLED (default off); policies configurable via IDME_POLICIES. Store only `humanVerifiedAt`, `idmeHash` (HMAC of subject, one identity per account), and `affiliations[]` (policy handles). Its only mechanical effect is one extra counted vouch; affiliations are badges and responder-registry signal, never power, and never gate credit, disputes, proposing, or voting.
- **Mediator lottery.** Draws are seeded from the drand beacon via `fetchBeacon`/`seededDraw` (src/lib/beacon.ts) and logged to `Circle.drawLog` (source, round, seed, pool, drawn). Never use Math.random for the lot; keep draws recomputable from the log.
- **Seed bank.** Varieties are `SeedShare`; borrow/return is `SeedRequest` (REQUESTED -> GIVEN -> RETURNED). Gift-first: no Grace pricing. Pure labels and seasonal logic in `src/lib/seeds.ts`; copy pins/locality from the steward at creation like other published records.
- **Tamper-evident ledger.** Every economic event appends to the hash chain via `appendLog` (`src/lib/hashlog.ts`) inside the same transaction as the record. Ledger records are append-only: never delete transfers/adjustments/vouchers in app code (only test teardown does, cleaning its own tail log entries). `verifyLedger` re-derives and checks the chain.
- **Vouchers.** Signed by the commons key derived from SESSION_SECRET (`src/lib/voucher.ts`, secret; pure crypto in `voucher.shared.ts`). Issue debits the issuer (a reservation, respecting standing limits); redeem credits the redeemer; the nonce is single-use so double-spend is detected. Zero-sum now includes outstanding ISSUED vouchers. Bare hashes prove nothing; always sign.
- **Trust preview.** `getTrustPreview`/`trustFlags` (`src/lib/trust.ts`) show only already-public signals before a transfer. Never surface anything private.
- **Jubilee.** `windDownReport` (`src/lib/jubilee.ts`) is a read-only mirror; wind-down is never an executable action in the app.
- **Cash (hash-commitment notes).** `src/lib/cash.ts` is pure (no db, safe for the browser); the secret is generated and hashed client-side in `mint-cash.tsx` and only the commitment reaches the server (`mintCash`). Never store or log the secret. Reclaim hashes the revealed secret to find the LOCKED commitment; first reveal wins. Keep `commitmentInput` byte-identical to the client's WebCrypto input. Zero-sum now also includes LOCKED cash denominations.
- **Checkpoints & export.** `src/lib/checkpoint.ts` (server: sign/export, reuses the commons key) + `checkpoint.shared.ts` (pure verify). `exportLedger` emits the hash chain + a signed checkpoint; `verifyExportedBundle` re-derives it with no DB. Export reveals only commitments, never who-paid-whom. `/verify` and `/api/ledger/export` are the UI.
- **Consolidation.** Cash (hash-locked, self-custody) is the promoted offline-money instrument. Vouchers are retired: `/vouchers` keeps redeem/void so outstanding notes settle, but minting is gone and it is off the nav. Do not build new voucher features.
- **Identity keys.** `User.publicKey` (Ed25519, hex) is the only thing the server holds; the private key lives in the member's browser (`use-local-identity.ts`, localStorage `fw_identity`). Vouches carry `signature` over `vouchToken(fromId,toId)` verified against `from.publicKey` (`src/lib/keys.ts`, pure). Signing is optional; a supplied signature must verify. `/api/trust/export` + `verifyTrustBundle` let other nodes verify the web of trust off-server. Never accept or store a private key server-side.
- **The critic.** `src/lib/sabul.ts` is read-only self-audit; findings are mirrors, never verdicts, and must never gate anything. Every finding carries an `action` (what one member can do, linked to the page where they do it). The answer to creeping power is always distributed to members; never add a role that acts on findings or removes people (no "social workers").
- **Infrastructure funding.** `/support` is a donation link (SUPPORT_URL) kept fully separate from Grace. Never add a fee on trades, never sell Grace, never hold a fiat reserve: that would be money transmission and would break the zero-sum, non-seizable design.
- **Security rules.** Pure rules live in `src/lib/security.ts` (password policy, rate-limit decision, session-version check, CSP builder, static headers) and are tested by `smoke:security`; `ratelimit.ts` counts attempts in `AuthAttempt` (throttling data, pruned after a day, not ledger). Session cookies carry `sv` and are dead when it differs from `User.sessionVersion` (bumped by change-password / log out everywhere). `src/proxy.ts` mints a nonce per request and sets the CSP; keep `script-src` nonce+strict-dynamic, never add `unsafe-inline` to scripts. The commons key seeds from `COMMONS_KEY_SEED` (fallback `SESSION_SECRET`); rotate them independently. Never deny geolocation in Permissions-Policy (the pin picker has a button).
- **Map look.** Map tokens are `map-land`/`map-water`/`map-road`/`map-label` (colors, per scheme), `map-filter` (kind `filter`: only invert/hue-rotate/brightness/contrast/saturate/grayscale/sepia/opacity with numeric args, or `none`; applied to raster tiles), and `map-glow` (shared length). `MAP_PRESETS` in theme.ts (Cypherpunk is the default) are applied with `applyMapPreset`; the editor shows a live preview. `elevation` (shared length) drives the derived `--shadow-*` variables in globals.css; use `shadow-card`/`shadow-raised`/`shadow-menu`/`shadow-inset` utilities, never literal shadows, so `0px` makes the UI flat again.
- **Maps.** Both maps call `addBasemap` (`src/components/basemap.ts`). With `NEXT_PUBLIC_PMTILES_URL` set, the base map is drawn from a self-hosted PMTiles file with rules that read theme tokens (`map-land`, `map-water`, `map-road` plus text/border/accent) through `paletteFromTokens` (`src/lib/map-theme.ts`, pure); otherwise raster tiles. Layer/kind names follow the Protomaps basemap schema (docs/maps.md). Never add a geocoder or search box.
- **Show the work.** Computed rules record their steps with `Work` (`src/lib/worked.ts`) in the same pass that computes the result: `computeStandingWithWork` (constants in `STANDING_RULES`), `explainDemurrageRun`, `explainZeroSum`, `explainKeeperPool` (`src/lib/explain.ts`). `zeroSumParts()` is the single zero-sum computation (locked cash in cents); the wind-down report uses it. When changing a rule, change its steps in the same function; `smoke:explain` fails if steps and result disagree.
- **Lockfile.** Heroku's "npm lockfile is not in sync" comes from npm on Windows pruning lock entries that only platform-skipped optional packages need (`@emnapi/core`, `@emnapi/runtime`, wanted by the wasm32-wasi builds of tailwind, sharp and the eslint resolver). They are therefore regular `dependencies`, never `optionalDependencies`; do not move them back. `npm run lock:check` (also run by postinstall) verifies every lock edge resolves path-aware; `npm run lock:fix` repairs by copying only the missing entries from a fresh resolution. Run `lock:check` before pushing whenever package.json changed.
- **Self-description.** `/about` and `/api/about` are generated from `src/lib/manifest.ts`, shaped by `manifest.schema.ts`: a capability needs `doesNot` (>=1) and `verifiedBy`, a principle needs `brokenIf`, an answer needs `limits`. The manifest is parsed at import, so a claim missing its limits breaks the build. Live figures come from `manifest.live.ts` (aggregates only, never a person; session-gated on the API). When adding a feature, add its capability with honest limits and a real check; `smoke:about` fails if a route, script, file or live key it names does not exist.
- **Claim audit.** `npm run audit:claims` runs the checks every manifest claim names (deterministic, offline, proof) and then sends each claim with that evidence to TypeSafe System One (`src/lib/audit.questions.ts`, questions with fixed answer spaces; `@typesafe-ai/sdk` is a devDependency and is never imported by the app). Confidence gates the report: act above 0.9, route to a person below 0.5. `--dry` writes the questions and evidence to audit-claims.json without sending. `smoke:audit` proves every claim is covered and every question has a reading that can fail. Never let a model answer gate anything at runtime: a model with power here would be the authority this design exists without.
- **Prices.** Nobody sets a price. `src/lib/pricing.ts` (pure) holds the rules: `referenceFrom` is the median of settled Grace transfers against listings, shown only from `REFERENCE_MINIMUM_EXCHANGES` (3) within `REFERENCE_WINDOW_DAYS`; `askSignal` notes only an OFFER of a `SURVIVAL` category above `HIGH_ASK_FACTOR` times that, never a NEED; `defaultSettlementFor` starts survival listings as a gift and care/skills/knowledge in Hours. `pricing.data.ts` scopes references to the viewer's locality or `NEAR_KM`. Render through `HighAskNote`/`PulseByCategory` (`src/components/pricing-views.tsx`). Signals and defaults only: never block, cap, hide, rank or penalize a listing by price, and never feed price into standing. The pulse by category shows a category only from `PULSE_MINIMUM_ANSWERS` so no single answer is readable.
- **Commons.** A shared thing is governed by its record (`CommonsEntry`: TOOK/RETURNED/USED/TENDED, written by anyone, never approved, never deleted) and its users, not by the steward alone. Pure rules in `src/lib/commons.ts`: `commonsUsers` (use entries plus the steward; a NOTE does not make a user; `before` stops joining the record to vote), `stewardIsSilent` (measured from the thing's own record, `STEWARD_SILENT_DAYS`; never add login tracking for this), `quorumFor`, `decideOutcome`. Questions about a commons are `Proposal` rows with `commonsId` and `commonsAction` (RULES or STEWARD); voters are `eligibleVoterIds` (users as of the question, verified), and `settleCommonsDecisions()` carries a closed result out lazily, claim-then-apply in one transaction, because nobody else can. Handover needs the recipient's acceptance. A NOTE about an entry is a word before a dispute and must never affect standing. Never ration, count stock, or auto-penalize use; never add recall of an active steward.
- **Null versus never written.** On MongoDB a filter for `field: null` does not match a document where the field was never written, and Prisma omits empty optional fields on create. Use `stillCurrent()`/`postedEverywhere` (`src/lib/where.ts`) and `NOT_YET_APPLIED` (`commons.data.ts`), or add `{ field: { isSet: false } }` alongside null. `smoke:where` holds these to live data.
